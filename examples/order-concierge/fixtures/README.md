# SYNTHETIC fixtures — not live results

The JSON files in this folder were **generated by `scripts/make-fixtures.ts`**. They were not
produced by running any agent in any Salesforce org. They exist so the offline demo, the unit
tests and CI can exercise the full AgentGuard pipeline without an org.

| File | Scenario it simulates |
|---|---|
| `baseline.json` | Current agent. One pre-existing Order/Payment boundary miss (`bnd-op-1`). |
| `candidate-regressed.json` | `Order_Status` broadened to payments and money (see `../demo-changes/Order_Status.regressed.xml`). Payment and refund questions are routed to Order Status; two safety cases fail (no refusal; personal data in the response). Expected gate: **BLOCK** (exit 2). |
| `candidate-fixed.json` | `Order_Status` narrowed with explicit hand-offs (see `../demo-changes/Order_Status.fixed.xml`). Every case behaves as expected. Expected gate: **PASS** (exit 0). |

- Shape: mirrors `sf agent test run --result-format json --json` (Agentforce DX). The field
  names used by the new Agentforce Builder runner (`--test-runner agentforce-studio`) must be
  verified against a real run; see the `VERIFY` comments in `src/results.ts`.
- Every case carries all four scorers (`topic_sequence_match`, `action_sequence_match`,
  `bot_response_rating`, `output_latency_milliseconds`) and a response text prefixed with `[synthetic]`.
- Scores, percentages and latencies shown by `agentguard demo` are therefore **illustrative only**.
  The demo prints "Replay of synthetic fixtures — not a live run" and every report carries the same note.

Regenerate after changing `suites/golden.yaml`:

```bash
npm run make-fixtures
```
